## 二、你列的 9 个风险点 → 逐条判定

### 1. 目标 EXE 最大化后是否必须覆盖任务栏
**真问题，v1.1 已按你的建议处理。**
- 默认 `TargetMode = Maximize`：只发 `SW_MAXIMIZE`（= SW_SHOWMAXIMIZED），**不覆盖任务栏**，不改窗口几何尺寸，对程序行为零侵入。
- 需要覆盖时把配置界面切到「最大化 + 强制覆盖任务栏」：先最大化，再 `SetWindowPos(HWND_TOPMOST, 0,0,W,H, SWP_SHOWWINDOW|SWP_NOOWNERZORDER)`。
- 该开关**默认关闭**（配置界面里排第一项的是"最大化（推荐）"），符合你"先基础版、稳定后再开"的节奏。

### 2. Chrome F11 全屏判断
**真问题，已经严格实现，并且给了实测手段。**
- 判断方法：`GetWindowRect(hwnd)`（窗口当前矩形）对比 `MonitorFromWindow + GetMonitorInfo(rcMonitor)`（显示器完整矩形），容忍 4px。
- 已全屏 → **不发 F11**（否则会把 Chrome 的全屏切掉）；未全屏 → 发 F11，320ms 后**回检**，仍未铺满则回退 Win32 覆盖。
- 关于"判断可能有误差"：Chrome 的 F11 真全屏窗口矩形与显示器矩形是**完全相等**的，误差 0；真正要小心的是"最大化窗口"（Win10/11 最大化矩形会比工作区外扩约 8px），而 8px > 4px 容差，所以会被正确判为"未全屏"→ 发 F11，这正是我们想要的行为。
- **实测手段**：每次切换都会往 `app.log` 写两行实测值，直接看日志就能验证，不用靠猜：
  ```
  F11 判断(Chrome): 窗口矩形=(0,0)-(1920,1080) 显示器矩形=(0,0)-(1920,1080) 覆盖=True 最大化=False
  F11 发送后(Chrome): 窗口矩形=(0,0)-(1920,1080) 显示器矩形=(0,0)-(1920,1080) 覆盖=True 最大化=False
  ```
  覆盖=False → 说明发了 F11 也没全屏，日志会紧跟一行"回退 Win32 覆盖任务栏"。

### 3. 点击悬浮按钮时焦点被抢
**真问题，v1.0 就已经处理了，做法和你说的一致。**
- 悬浮窗 `SourceInitialized` 时加 `WS_EX_NOACTIVATE` 扩展样式（XAML 同时 `ShowActivated=False`、`Focusable=False`）→ 点它**不抢前台焦点**，`GetForegroundWindow()` 还是被切换的程序。
- 另外按你说的加了内部记录 `lastActive`：`ToggleService._lastForegroundPath`。当前台是"其它程序"时用它判断方向（第一次运行为空 → 默认切 Chrome）。
- 注意一个副产品：`WS_EX_NOACTIVATE` 的窗口不会被系统自动置顶到全屏窗口之上，所以切换完成后会 `SetWindowPos(HWND_TOPMOST, SWP_NOACTIVATE)` **延时重压 3 次**（400ms 间隔），保证按钮不被全屏窗口盖住。

### 4. Chrome 多进程窗口识别
**前半句真问题（已处理），后半句"窗口尺寸接近屏幕"作为过滤条件会出 bug，不能加。**
- 已实现的过滤链：`IsWindowVisible` → `GetWindowTextLength>0` → `GW_OWNER == 0` → 非 `WS_EX_TOOLWINDOW` → 进程完整路径比对。Chrome 那几十个无标题的隐藏窗口在第二关就被全部拦掉。
- **不能加"尺寸接近屏幕"**：用户刚打开 Chrome、还没进全屏时窗口尺寸不是全屏尺寸，加了这条就**找不到 Chrome** 了——正好把主功能干掉。尺寸只能用来"选窗口"（多窗口时偏好大的），不能用来"筛窗口"。
- 多窗口时怎么选：取 `EnumWindows` 回调顺序里**第一个命中**的（EnumWindows 本身就是 Z 序前→后，等价于"最近激活/最前面"那个）。

### 5. 权限问题（UAC）
**真问题，你说的权衡成立，v1.1 给了完整方案。**
- 事实：目标程序以管理员运行时，普通权限进程**无法** `SetForegroundWindow` 它的窗口、也**无法**给它发 F11（UIPI 硬限制，任何工具体系都绕不过）。
- v1.0：manifest 用 `asInvoker`（普通权限，日常不弹 UAC）+ 启动时检测 + 托盘气泡提示"请以管理员身份运行"。
- v1.1 新增（按你"改用任务计划程序自启"的建议）：压缩包里多了两个批处理
  - `自启-任务计划程序-安装.bat`：创建登录触发的计划任务，`/RL HIGHEST`（最高权限）+ `LogonType Interactive` → **登录后静默以管理员权限启动，不弹 UAC**（这是正经做法，不是绕过安全机制）。
  - `自启-任务计划程序-卸载.bat`：删除该任务。
  - 用它的时候请在配置界面**取消勾选「开机自启」**，避免 Run 键和计划任务双启动（有单实例保护，不会重复运行，只会多一次进程启动动作）。
- 建议路径：**优先让目标 EXE 不以管理员运行**（最省事）；确实必须管理员，就用计划任务方案。

### 6. 自启路径失效（EXE 移动后）
**真问题，v1.0 已处理。**
- 程序**每次启动**都会按当前配置重新同步注册表 Run 项：`AutoStart=true` 时值不等于当前 EXE 路径就重写，`false` 时删除该项。EXE 换目录后启动一次，注册表自动纠正。
- 计划任务那条路的路径是写死的，**移动 EXE 后重跑一次安装.bat** 即可（脚本里已写明提示）。

### 7. 配置保存位置（Program Files 无写权限）
**真问题，v1.1 新增处理，但我不完全同意直接搬到 %AppData%。**
- 做法：**EXE 同目录优先**（便携、符合你原始需求，U 盘/桌面照常跑）；启动时真写一个临时文件探测目录是否可写，不可写才回落到 `%AppData%\SelfSwitch\`，并：
  - 托盘气泡告知"配置位置已调整"；
  - 若 EXE 目录里已存在旧 `config.json`，自动复制到新目录，避免"配置突然变回默认"；
  - 托盘菜单/配置界面保存后仍会显示实际保存路径。
- 为什么不默认就放 %AppData%：单文件工具的使用场景就是"扔一个文件夹里双击运行"，配置跟着 EXE 走最直观；只有真遇到权限问题才回落。

### 8. 切换时当前窗口处理
**已按你的口径实现。**
- 默认「最小化」：先 `SetWindowPos(HWND_NOTOPMOST)` 取消置顶，再 `ShowWindow(SW_MINIMIZE)`（先取消置顶很重要，否则最小化动画会有置顶残影）。
- 可选「留在后台」：只取消置顶 + 让出焦点，不最小化。
- 二者都配置界面可切。

### 9. 目标 EXE 窗口识别（多窗口）
**真问题，v1.1 按你的建议加了标题关键字，但仍保留 Z 序兜底。**
- 新增配置项 `WindowTitleKeyword`（配置界面第 3 行，**默认空**）：
  - 留空 → 只用路径识别，取 Z 序最前窗口（默认行为，和 v1.0 一致）；
  - 填写 → 还要求窗口标题**包含**该关键字（忽略大小写）；路径匹配上但标题都不符时，视为"未找到"并写日志，**不会**误切到别的窗口。
- 为什么不做成必填：很多程序主窗口标题会带文件名/版本号，强制填关键字反而容易找不到。

## 三、"三、核心切换逻辑" → 实现对照

| 你的步骤 | 实现 |
|---|---|
| 1 点击悬浮按钮 | `RootBorder_MouseLeftButtonUp` → `ToggleService.Toggle()`（`Monitor.TryEnter` 防重入） |

## 五、仍然存在的客观限制（不是 bug，是 Windows 机制）

1. 普通权限控制不了管理员权限的窗口（UIPI），必须提权或让目标程序降权运行。
2. F11 / Alt+Enter 依赖目标程序自身支持，不支持时已自动回退；个别 DirectX 独占全屏的程序对 `SetWindowPos` 也不买账。
3. 同一程序若有多个顶层窗口，工具只会操作 Z 序最前（或标题关键字命中）的那一个。
4. 切换动作在 UI 线程同步执行（发键后要等回检），单次 0~700ms，这期间点击会被防重入逻辑忽略——刻意设计。
5. 本工程已在本机完成编译与单文件发布验证（0 警告 0 错误），但**窗口切换行为必须在 Windows 上实测**，实测看 `app.log`。

## 七、v1.3 新增：悬浮按钮文字随前台窗口变化

### 需求原文
> "悬浮按钮如果是谷歌浏览器显示文字可以自定义，其中如果是目标的 exe 程序，UI 中的文字也可以自定义。"

### 理解与确认结果

| 确认项 | 你的选择 | 实现 |
|---|---|---|
| 文字表达什么 | **"点下去会切到哪里"** | 前台是 Chrome → 显示"切到目标程序"；前台是目标程序 → 显示"切到浏览器" |
| 什么时候刷新 | **实时跟随（后台轻量检测）** | `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` 事件驱动 + 1 秒兜底轮询 |
| 前台都不是时显示什么 | **第三套自定义文字** | 默认 `—`（配合严格模式：此时点按钮没反应） |

### 三套文字（配置界面第 3~5 行，都可改）

| 前台窗口 | 按钮显示（默认） | 点下去的后果 |
|---|---|---|
| Chrome | `切到目标程序` | 切到目标 EXE |
| 目标 EXE | `切到浏览器` | 切到 Chrome |
| 其它程序 | `—` | **什么都不发生**（严格模式） |

### 新增配置项

| 字段 | 类型 | 默认 |
|---|---|---|
| `ButtonTextWhenChrome` | string | `切到目标程序` |
| `ButtonTextWhenTarget` | string | `切到浏览器` |
| `ButtonTextOther` | string | `—` |

`ButtonText`（老字段）保留但**不再使用**，只为兼容旧 config.json；旧的配置文件可直接替换使用。

### 技术实现与开销

- `ForegroundWatcher.cs`：前台事件钩子（out-of-context，不注入任何进程）+ `DispatcherTimer` 1 秒兜底轮询。
- **只有前台窗口句柄变化时才解析进程路径**（一次 `OpenProcess` + `QueryFullProcessImageName`），句柄没变直接 return → 1 秒轮询的常驻开销可忽略。
- 只在分类**发生变化**时刷新文字，不做任何过渡效果（符合"无动画"）。
- 按钮宽度会随文字变化，按钮是右下角锚定的，宽度变化只影响左边缘；`SizeChanged` 里重算位置，不会跑偏。
- 两个实现要点：钩子委托用静态字段保持强引用（否则被 GC 回收后回调崩溃）；配置里路径改了要 `Invalidate()` 强制重判。

### 需要知道的一点

**打开配置窗口时，前台是工具自己**，所以按钮会显示第三套文字（`—`）——这是"实时跟随"的正常表现，
关掉配置窗口、焦点回到 Chrome 或目标程序后，文字会立刻跟着变回来。

### 影响面
- 新增文件 `ForegroundWatcher.cs`；改动 `AppConfig.cs`、`MainWindow.xaml.cs`、`ConfigWindow.xaml(.cs)`、`App.xaml.cs`、`Win32Helper.cs`、`config.json`、`build.bat`。
- 版本号升到 **1.3.0**。

## 八、v1.4 新增：其它程序在前台时自动隐藏悬浮按钮

### 需求原文
> "其他程序自动隐藏"

### 理解
**当前台窗口是"其它程序"（既不是 Chrome 也不是目标 exe）时，悬浮按钮自动隐藏**——不再显示那个 `—`，
直接看不见。和 v1.2 的严格模式是同一套逻辑：这种状态下点按钮本来也不会切换，干脆不显示。

> 如果你说的其实是别的意思（比如"切换时自动隐藏别的程序窗口"），直接说一声，我改。

### 实现

| 项目 | 说明 |
|---|---|
| 配置项 | `HideButtonWhenOther`（bool，**默认开启**），配置界面第 12 行可勾选 |
| 判断依据 | 复用 v1.3 的 `ForegroundWatcher`，前台分类为 `Other` → 隐藏；回到 `Chrome`/`Target` → 立即显示 |
| 隐藏方式 | `Visibility.Hidden`（不是 Collapsed）：保留布局，`ActualWidth` 仍有效，重新显示时不闪 |
| 关键防护 | `BringToFront()` 加了显示状态判断——`Win32.EnsureTopmost` 带 `SWP_SHOWWINDOW`，不拦住的话切换后那 3 次"重新置顶"会把隐藏的按钮弹出来 |
| 隐藏后怎么操作 | 托盘图标不受影响：右键 = 打开配置 / 退出程序，双击 = 等同于点悬浮按钮 |
| 怎么让它回来 | 把 Chrome 或目标程序切到前台（Alt+Tab），按钮立刻自己出现，位置文字都对 |

### 行为汇总（v1.4 后的完整状态表）

| 当前前台 | 按钮显示 | 按钮文字（默认） | 点下去的后果 |
|---|---|---|---|
| Chrome | 显示 | `切到目标程序` | 切到目标 EXE（F11 方式） |
| 目标 EXE | 显示 | `切到浏览器` | 切到 Chrome（最大化方式） |

## 十、v1.6：现场故障处置（"绑定之后无法切换"）

### 现场现象与根因
用户上传 `app.log` + `config.json`，日志给出的证据链：

```
[20:53:34] 前台窗口类别变化: Other | title="豆包" class="Chrome_WidgetWin_1"     ← 豆包窗口在前台
[20:55:41] 切换方向: 前台是其它程序(D:\Doubao\app\Doubao.exe) → 目标=目标 EXE   ← 真实进程路径
[每次都]   提示: 未找到目标 EXE 窗口 ... 路径：D:\Doubao\Doubao.exe             ← 配置里的路径
```

**根因：目标路径写错了一层目录**。配置写的是 `D:\Doubao\Doubao.exe`（桌面快捷方式指的那个），
实际在跑的进程是 `D:\Doubao\app\Doubao.exe`。于是：

1. `WindowFinder` 永远找不到目标窗口 → 每次点击都只是弹一句"未找到目标 EXE 窗口"；
2. 豆包被归类为"其它程序" → 严格模式**静默忽略**点击、按钮还**自动隐藏**；
3. 用户着急连点 → v1.5 的 400ms 节流把后续点击也吞掉（日志里 10+ 条节流告警）。

三件事叠加，表现就是"点了完全没反应"。

### 用户侧解法（10 秒）
把配置里的目标路径改成 `D:\Doubao\app\Doubao.exe` 即可。

### 代码侧加固（v1.6 本次改动）

| # | 改动 | 目的 |
|---|---|---|
| 1 | **自动诊断同名进程**：找不到窗口时枚举同名进程的可见窗口，把真实路径写进气泡 + 日志 | 以后再写错，工具直接告诉你正确路径，不用翻任务管理器 |
| 2 | 配置界面两个路径框各加「**取当前窗口**」按钮 | 一键填入真实路径，从源头杜绝抄错；实现用 `ForegroundWatcher.LastForeignPath`（点按钮会让配置窗口变成前台，实时取会取到自己） |
| 3 | 新增 `IgnoreShellWindows`（默认开）：通知横幅/任务栏/操作中心抢前台时，不改按钮状态、不参与方向判断 | 现场 4 分钟里 10 次系统通知抢前台 → 按钮反复隐藏 + 严格模式误判定，全是干扰 |
| 4 | 节流只在**切换成功**后计时，失败不占节流窗口 | 找不到窗口时用户重试不再被拦 |

### 新增配置项
| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `IgnoreShellWindows` | bool | `true` | 忽略系统壳窗口（通知横幅/任务栏/操作中心/托盘旋出窗）对按钮状态与切换判断的影响 |

### 下一步建议（现场验证）
1. 用「取当前窗口」重填两个路径 → 保存 → 点按钮，应当立即双向切换。
2. 故意把路径改错一层 → 点按钮 → 气泡里应出现"【疑似路径写错】检测到同名的程序窗口在：…"。
3. 手机上给电脑发条消息让系统弹出通知 → 按钮不应消失，点击仍正常。

### 影响面
- 改动：`WindowFinder.cs`（同名窗口诊断）、`ForegroundWatcher.cs`（壳窗口过滤 + 记录最近前台路径）、`ToggleService.cs`（壳窗口判定 + 失败不节流 + 诊断气泡）、`AppConfig.cs`、`ConfigWindow.xaml(.cs)`、`config.json`、`build.bat`。
- 版本号升到 **1.6.0**。

## 十一、v1.7：浏览器侧也做成"显示方式可选"（8 选 1）

### 需求原文
> "给刚刚游览器也加一下，可以设置各种类型，最大化，窗口化这些选项，其他的你也判断是否可以加"

### 做了什么
把原来只给目标 EXE 用的 4 种方式，**升级成 Chrome 与目标 EXE 共用的一套 8 种显示方式**，
两个程序各自独立设置（原 `ChromeFullscreen` / `TargetFullscreen` 两个枚举合并为 `WindowDisplayMode`）。

| # | 显示方式 | 效果 | 覆盖任务栏 |
|---|---|---|---|
| 1 | `SendF11` | 发 F11 原生全屏；已全屏则跳过，不支持则回退覆盖任务栏 | 是 |
| 2 | `CoverTaskbar` | 铺满整屏 + 置顶 | 是 |
| 3 | `Maximize` | 普通最大化 | 否 |
| 4 | `MaximizeCoverTaskbar` | 最大化后再铺满 | 是 |
| 5 | **`Windowed`（新增）** | 窗口化：恢复成普通窗口，保留自身尺寸位置 | 否 |
| 6 | **`CustomRect`（新增）** | 按 `x,y,w,h` 摆放，**支持百分比**，可做左右分屏 | 否 |
| 7 | **`KeepCurrent`（新增）** | 只切前台，完全不碰窗口大小位置 | 否 |
| 8 | `SendAltEnter` | 发 Alt+Enter（Chrome 侧也放开） | 取决于程序 |

### "其他能不能加"的判断结果

**加了 3 个**：
- **窗口化**（你点名要的）；
- **自定义区域**——窗口化不给尺寸其实没意义（窗口可能小得看不见或跑到屏幕外）；支持百分比后，"左右分屏"变成一行配置：Chrome 填 `0,0,50%,100%`、目标填 `50%,0,50%,100%`（**默认值已经是这个，切一下模式就能用**）；
- **保持当前状态**——有些程序（浏览器套壳客户端等）自己管窗口，工具别去动它。

**没加 2 个（判断后放弃）**：
- "是否置顶"独立开关：`CoverTaskbar` 已经覆盖，单独置顶容易压住所有窗口反而切不回来；
- "最小化目标窗口"：那不叫显示方式，需要就用 `KeepCurrent`。

### 兼容性
- 枚举按**名称**序列化，历史取值全部保留 → **旧 config.json 直接能读**，不用重配。
- 配置界面下拉项改为"数组映射索引"（`ModeValues` / `ModeNames`），不再依赖枚举数值顺序。

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `ChromeRect` | string | `0,0,50%,100%` | Chrome 自定义区域，仅 `CustomRect` 模式生效 |
| `TargetRect` | string | `50%,0,50%,100%` | 目标 EXE 自定义区域，仅 `CustomRect` 模式生效 |

区域格式 `x,y,w,h`，每项可为像素或百分比；非法值会被 `Normalize()` 回落默认并写 WARN，运行时再校验一次、非法则本次退回最大化。

## 十五、v1.10.0：现场日志定位到"点击被吃掉"的真根因

### 现场日志（用户上传，579 行）关键片段

```

21:40:00.453 前台是其它程序 → 悬浮按钮已自动隐藏

（21:40:00 / :07 / :19 / :26 重复 4 次，且都没有 查找结果: 行）
```

### 根因（完整因果链）

## 十六、v1.11.0：位置调整挪进配置界面，按钮只负责"单击=切换"

### 需求原文
> "这个是移动的在设置里面进行，点击之后可以进行拖动，单击 UI 进行切换，这样不影响单击切换"

### 设计变化
把"移动按钮"和"单击切换"彻底拆开，永不再互相干扰：

| 能力 | 之前（v1.8~v1.10） | 现在（v1.11） |
|---|---|---|
| 单击悬浮按钮 | 要先用 4 DIP 阈值判断"是点击还是拖动"，有误判风险 | **只做切换**，没有任何拖动判定 |
| 调整位置 | 在按钮上按住拖动（拖完松手还可能误触发切换） | 配置界面 →「按钮位置」→「**调整位置**」 |

### 「调整位置」的操作流程
1. 配置界面点「调整位置」→ **配置窗口自动隐藏**，托盘弹出提示"移动鼠标…单击确认，Esc 取消"；
2. 悬浮按钮的**中心跟着鼠标走**（30ms 轮询 `GetCursorPos`，不依赖窗口被激活）；
3. 移到想要的位置 → **单击一下** → 位置写入 `config.json`（`FreePosition=true` + `FreeX/FreeY`），托盘气泡回报坐标；
4. 配置窗口自动显示回来，位置提示变成"当前位置：调整后的位置 (X=…, Y=…)"。
5. 中途不想改了 → 按 **Esc**，按钮回到调整前的位置。

### 三个容易踩的点（都已处理）
- 跟随不能用 `MouseMove`：窗口没被激活就收不到事件 → 用 `GetCursorPos` 轮询；
- 确认不能用窗口的 `MouseLeftButtonUp`：同理 → 用 `GetAsyncKeyState(VK_LBUTTON)` 轮询；
- **进入后 500ms 内不认确认**：否则"点『调整位置』按钮"的那一下就把它当成确认了，位置会定死在配置窗口旁边。

### 兼容
不新增配置项（沿用 `FreePosition/FreeX/FreeY`），老 `config.json` 直接可用；「复位到锚点」和「锚点 + X/Y 偏移」都保留。

### 影响面
- 改动：`MainWindow.xaml(.cs)`（删除拖动逻辑，新增位置调整模式）、`ConfigWindow.xaml(.cs)`（「调整位置」按钮 + 提示文字）、`App.xaml.cs`（隐藏/恢复配置窗口）、`Win32Helper.cs`（`GetCursorPos`/`GetAsyncKeyState`）。
- 版本号升到 **1.11.0**。
