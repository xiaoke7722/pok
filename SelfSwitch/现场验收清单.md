# SelfSwitch v1.8 现场验收清单（10 分钟）

> 背景：v1.5 ~ v1.8 都是在 Linux 上编译验证的（0 警告 0 错误），**窗口/鼠标行为没在 Windows 上跑过**。
> 下面 11 条按"最可能出问题 → 最不容易出问题"排序，**第 1~3 条一定要跑**。
> 每条都给"怎么做 / 看什么 / 期望值"，不用猜。

---

## 先做这个：3 秒确认你跑的是不是新版本

| 怎么查 | 新版（1.9.1）应该看到 | 如果看到这个 → 你跑的是旧版本 |
|---|---|---|
| 打开 `app.log` **第一行** | `=== SelfSwitch 启动 === 版本=1.9.1 exe=…` | 没有 `版本=` 字段 |
| 鼠标悬停**托盘图标** | 提示 `SelfSwitch 窗口切换工具 v1.9.1（双击=切换）` | 没有版本号 |
| 文件属性 → 详细信息 → 文件版本 | `1.9.1.0` | 1.8 或更低 |

> 最常见的坑：**桌面快捷方式 / 自启项指向的是旧的 EXE**（比如 `D:\PCdate\顾桥电厂\切换工具\SelfSwitch (4).exe`）。
> 双击看的是快捷方式，实际跑的可能是旧文件。请到固定目录里直接双击**最新的那个** EXE。

---

## 0. 准备：固定目录，清理副本（**先做这个**）

现在机器上可能有 `SelfSwitch.exe`、`SelfSwitch (2).exe`、`SelfSwitch (4).exe`、小体积版…… 建议：

1. 选一个固定目录，例如 `D:\PCdate\顾桥电厂\切换工具\`，**只保留一个** `SelfSwitch.exe`（建议用 228KB 的小体积版）和 `config.json`。
2. 另外几个副本**改名或移走**（不要直接删，留个备份）。
3. 双击运行固定目录里那个，然后看：
   - `app.log` 第一行 `exe=` 后面应是**固定目录**的路径；
   - 注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 里 `SelfSwitch` 的值也应指向它。

> 坑：本工具有单实例保护（互斥量名字固定）+ 自启项名字固定 → 同时跑两个副本时，**后启动的那个会静默退出**，表现为"我明明双击了却没反应"。所以只留一个副本。

## 1. 拖动摆放（v1.8 新代码，没跑过，**优先验证**）

| 步骤 | 期望 |
|---|---|
| 按住悬浮按钮往屏幕中间拖 | 按钮跟着鼠标走，全程不透明 |
| 松手 | 停在松手位置；日志出现 `开始拖动悬浮按钮` 和 `悬浮按钮位置已记住（自由位置）: FreeX=…, FreeY=…` |
| 拖动后**单击**按钮 | 正常切换窗口（不应该被吃掉） |
| 拖到任务栏那一块 | 允许停在那里（不报错、不弹回去） |
| 右键 → 配置 → 点「复位到锚点」 | 按钮立刻回到右下角（锚点+偏移的位置），提示行变回"提示：按住悬浮按钮可直接拖…" |
| 重启程序 | 若没复位过，按钮应出现在**拖动记住的位置** |

**如果拖动有问题**（按钮乱跳/拖不动/拖完位置不对），把 `app.log` 发我，重点看有没有 `拖动悬浮按钮失败` 的 ERROR。

## 一、位置调整（v1.11 起在配置界面里做）

| 步骤 | 期望 |
|---|---|
| 配置界面 →「按钮位置」→ 点「**调整位置**」 | 配置窗口**自动隐藏**；托盘弹提示"移动鼠标…单击确认，Esc 取消" |
| 移动鼠标 | 悬浮按钮**跟着鼠标走**（按钮中心贴着光标） |
| 单击一下 | 位置被保存：托盘气泡回报 `X=…, Y=…`；配置窗口自动显示回来，提示行变成"当前位置：调整后的位置 (X=…, Y=…)"；`config.json` 里 `FreePosition=true` |
| 重启程序 | 按钮出现在刚才的位置 |
| 再点「调整位置」，移动后按 **Esc** | 按钮回到调整前的位置，配置窗口显示回来 |
| 点「复位到锚点」 | 清掉记录，回到「锚点 + 偏移」的位置 |

> **悬浮按钮上不再有拖动**：单击 = 切换，永远不会被拖动判定吃掉。

## 9. 资源占用（跑 10 分钟后看一眼）

任务管理器 → 详细信息 → SelfSwitch.exe：

- 内存：稳定在 **80~120 MB** 左右（WPF + 单文件自解压正常范围），**不持续上涨**；
- 句柄数：稳定，不持续上涨；
- CPU：空闲时应为 **0%**（每秒一次的兜底轮询几乎不耗 CPU）。

## 六、快速切换快捷键（v1.9 新增）

| 步骤 | 期望 |
|---|---|
| 默认按 `Ctrl+Alt+S`（Chrome 在前台时） | 立刻切到目标程序；再按一次切回 Chrome。日志：`全局快捷键触发切换（Ctrl+Alt+S）` |
| 把按钮拖到别处 / 让按钮自动隐藏（切到微信），再按快捷键 | 只要前台是 Chrome 或目标程序，照样能切（快捷键不依赖按钮可见） |
| 配置界面点进「快速切换快捷键」框，按 `Ctrl+Shift+F9` | 框里自动变成 `Ctrl+Shift+F9`；保存后按新键生效（日志：`已注册全局快捷键: Ctrl+Shift+F9`） |
| 取消勾选「启用」再保存 | 日志 `快速切换快捷键：已关闭`；按键不再触发 |
| 故意设成别的程序已占用的键（比如 `Ctrl+C`） | 托盘弹气泡 `快捷键注册失败…可能已被其它程序占用`，程序其它功能不受影响 |
| 退出程序 | 日志 `已注销全局快捷键`（不会残留占用） |

> 快捷键和点按钮**完全等效**：严格模式开着时，如果前台既不是 Chrome 也不是目标程序，按了也不会切换（日志写"静默忽略本次点击"）——想让它无条件切换，把「严格模式」取消勾选。

## 有问题时给我这三样

1. `app.log`（重点看：`查找结果:`、`切换方向:`、`F11 判断(Chrome)`、任何 `[ERROR]` 行）
2. `config.json`
3. 一句现象描述（点哪个按钮、屏幕上是啥样）

日志里每行都带毫秒时间戳，且 `前台窗口类别变化` 会记录窗口标题和类名 —— 基本能定位到具体哪个窗口出错。
