# SelfSwitch — Chrome / 目标 EXE 一键切换小工具

固定全屏的 Chrome 和某个业务程序之间来回切换，只点右下角那个半透明悬浮按钮。
**不启动、不关闭任何程序**，只切换已经打开的窗口。

---

## 1. 编译

双击 `build.bat`（需要已安装 .NET 8 SDK），或手动执行：

```bat
dotnet publish -c Release -r win-x64 --self-contained true /p:PublishSingleFile=true /p:IncludeNativeLibrariesForSelfExtract=true /p:EnableCompressionInSingleFile=true
```

产物（单个 EXE，无需安装 .NET 运行时）：

```
bin\Release\net8.0-windows\win-x64\publish\SelfSwitch.exe
```

把 `SelfSwitch.exe` 和 `config.json` 放到同一个文件夹即可（首次运行会自动生成 config.json）。

---

## 2. 首次配置

1. 运行 `SelfSwitch.exe`，右下角出现半透明「切换」按钮，托盘出现蓝色圆形图标。
2. **右键悬浮按钮 → 打开配置**（或双击托盘图标→打开配置）。
3. 填写：
   - **Chrome 完整路径**（例：`C:\Program Files\Google\Chrome\Application\chrome.exe`）
   - **目标 EXE 完整路径**（例：`D:\FleetView\FleetView.exe`）
   - 三套悬浮按钮文字 / 透明度 / 位置（锚点 + X/Y 偏移）
   - 全屏方式、切换时当前窗口的处理方式
   - 开机自启开关
4. 点「保存」，立即生效（配置写入 EXE 同目录 `config.json`）。

> 路径必须是**完整启动路径**（绝对路径 + 文件名），工具靠它识别进程，不靠窗口标题。
>
> **别用"桌面上那个快捷方式指向的文件"，要用"正在运行的那个进程的路径"** —— 两者经常不一样
> （例：豆包桌面图标是 `D:\Doubao\Doubao.exe`，真正跑的是 `D:\Doubao\app\Doubao.exe`）。
>
> **最省事的填法**：把这行的「**取当前窗口**」按钮用起来 ——
> 1）先把 Chrome 点到最前面；2）回来点 Chrome 那行的「取当前窗口」→ 路径自动填好；
> 3）再把目标程序点到最前面；4）回来点目标那行的「取当前窗口」。两步搞定，不会写错。
>
> 万一还是写错了：切换失败时工具会**自动去找同名进程的窗口**，在托盘气泡和 `app.log` 里直接告诉你正确路径。

## 3. 使用

| 操作 | 结果 |
|---|---|
| 左键点悬浮按钮 | Chrome ↔ 目标 EXE 来回切换（都不在前台时默认切到 Chrome） |
| **按住悬浮按钮拖动** | **拖到屏幕任意位置，松手自动记住**（位置写进 config.json，下次启动还在原地） |
| **按快捷键（默认 `Ctrl+Alt+S`）** | **不用点按钮直接切换**——和点按钮完全等效（同样受严格模式/防重入/节流约束）。可在配置界面改键或关掉 |
| 鼠标悬停按钮 | 透明度临时变为 100% |
| 右键悬浮按钮 | 打开配置 / 退出程序 |
| 双击托盘图标 | 等同于点悬浮按钮；托盘右键有同样的菜单 |

**悬浮按钮文字是动态的**：按钮文字会**实时跟随前台窗口**变化，显示的是"点下去会切到哪里"——

| 当前前台 | 按钮显示（默认） |
|---|---|
| Chrome | `切到目标程序` |
| 目标程序 | `切到浏览器` |
| 其它程序 | `—`，且**按钮自动隐藏**（默认） | 什么都不发生（严格模式）|

三套文字都可以在配置界面里改（配置界面第 3~5 行）。检测方式是 WinEvent 前台事件钩子 + 1 秒兜底轮询，
只有前台窗口句柄变化时才解析进程路径，开销可忽略。

**当前台是"其它程序"时，悬浮按钮会自动隐藏**（配置项 `HideButtonWhenOther`，默认开启）——
因为这种状态下点按钮本来也不会切换。隐藏期间：

- 托盘图标还在，右键托盘图标可打开配置 / 退出程序，双击托盘图标等同于点悬浮按钮；
- 把 Chrome 或目标程序切到前台（Alt+Tab），按钮**立刻自己出现**，位置和文字都对。
- 不想让它藏，在配置界面取消勾选「其它程序在前台时自动隐藏悬浮按钮」。
- **与严格模式联动**：取消勾选「严格模式」后，本项会自动失效——非严格模式下按钮在"其它程序"状态是有用的，藏起来就点不到了。

切换时：
- **前提（严格模式，默认开启）**：当前前台窗口必须是 Chrome 或目标 EXE 才会执行切换；否则点按钮**没有任何反应**（不切换、不提示，`app.log` 里会留一行记录）。想恢复"其它程序时也切"的行为，在配置界面取消勾选「严格模式」。
- **Chrome 与目标 EXE 各自按配置的「显示方式」摆放窗口**：默认 Chrome 发 F11、目标 EXE 普通最大化（两者都不覆盖任务栏）。8 种方式（F11 / 覆盖任务栏 / 最大化 / 最大化+覆盖 / 窗口化 / 自定义区域 / 保持当前状态 / Alt+Enter）在配置界面里各自独立设置，详见第 8 节。
- 原窗口默认最小化，可改为「留在后台」。

未找到窗口时弹出托盘气泡（同一错误 5 秒内不重复提示）。

## 4. 开机自启

默认开启。勾选/取消「开机自启」后保存即写入/删除注册表项：

```
HKCU\Software\Microsoft\Windows\CurrentVersion\Run  →  SelfSwitch = "...\SelfSwitch.exe"
```

程序每次启动都会按当前配置同步一次该注册表项（**EXE 换目录后启动一次即自动纠正路径**）。

### 备选：以管理员权限静默自启（不弹 UAC）

如果目标程序必须以管理员身份运行，用注册表方式启动的本工具会控制不了它的窗口。这时改用压缩包里的：

- **`自启-任务计划程序-安装.bat`**：创建一个"登录时触发 + 最高权限"的计划任务 → 登录后静默以管理员权限启动，**不弹 UAC**。
- **`自启-任务计划程序-卸载.bat`**：删除该任务。

> 用这个方式时，请在配置界面里**取消勾选「开机自启」**，避免 Run 键 + 计划任务双启动（有单实例保护，不会重复运行，只是多一次启动动作）。
> 该方案下 EXE 位置是写死在任务里的，**移动 EXE 后重跑一次安装.bat**。

## 5. 退出

右键悬浮按钮（或托盘图标）→ **退出程序**。退出时会移除托盘图标。
（任务管理器结束进程也可以，但建议走菜单，日志会记录退出时间。）

---

## 6. 管理员权限

- 默认以**普通权限**启动（manifest 里 `asInvoker`）。
- 若业务程序/Chrome 是**以管理员身份运行**的，普通权限无法控制其窗口，程序启动时会弹气泡提示「权限不足」。
  此时请：右键 `SelfSwitch.exe` → **以管理员身份运行**。
- 想每次都自动提权：把 `app.manifest` 里的
  `<requestedExecutionLevel level="asInvoker" ... />` 改成 `level="requireAdministrator"`，重新编译。
- 想"平时不弹 UAC、但开机就是管理员权限"：用 `自启-任务计划程序-安装.bat`（见上面第 4 节）。
- **建议**：能不让目标程序以管理员运行就别让它以管理员运行——这是最省事的路径。

## 7. 日志与排错

| 文件 | 说明 |
|---|---|
| `app.log` | 运行日志（启动、切换方向、查找窗口结果、F11 判断实测值、异常），超过 2MB 自动轮转 `app.old.log` |
| `config.json` | 当前配置；解析失败时旧文件备份为 `config.json.bad` 并回退默认值 |

两个文件都在 **EXE 同目录**；如果那个目录不可写（例如放进了 `Program Files`），程序会自动改存到
`%AppData%\SelfSwitch\`，并在启动时弹气泡告知（旧配置会自动搬过去）。

**F11 判断实测**：每次切到 Chrome 都会在 `app.log` 写两行实测值，直接看就知道判断准不准：

```
F11 判断(Chrome): 窗口矩形=(0,0)-(1920,1080) 显示器矩形=(0,0)-(1920,1080) 覆盖=True 最大化=False
F11 发送后(Chrome): 窗口矩形=(0,0)-(1920,1080) 显示器矩形=(0,0)-(1920,1080) 覆盖=True 最大化=False
```

`覆盖=True` 表示已铺满 → 不会再发 F11（避免把全屏切掉）；若发送后仍 `覆盖=False`，日志会紧跟一行"回退 Win32 覆盖任务栏"。

常见问题：

- **配好路径后完全切不动（最常见）** → 十有八九是**目标程序路径不对**。典型表现：`app.log` 里一直写"未找到目标 EXE 窗口"，同时又出现"前台是其它程序(D:\xxx\app\yyy.exe)"——那就是它在告诉你正确路径。用配置界面的「取当前窗口」按钮重填一次，或直接照日志里那行改。
- **点了没反应（再查这三条）** →
  1. **是不是被浮窗盖住了**：输入法状态条 / 系统通知横幅这类第三方置顶浮窗会压在按钮上（它们在右下角很常见）。用任务管理器看也行，最直接的办法是把「按钮位置」的 X/Y 偏移调大、或换一个锚点（比如右上角）再试。
  2. **是不是严格模式**：前台既不是 Chrome 也不是目标程序时，按设计就是静默忽略（`app.log` 里会写"严格模式：...静默忽略本次点击"）。
  3. **是不是节流**：距上次**成功切换**完成不到 400ms 的点击会被丢弃（防连点），`app.log` 里会写"距离上次切换完成仅 XXms（节流 400ms），忽略本次点击"。找不到窗口这类**失败不会触发节流**，可以直接重试。
  都不是的话，看 `app.log` 里的 `查找结果:` 和 `切换方向:` 两行，确认路径对不对、程序是不是真的开着。
- **切过去没有全屏/没盖住任务栏** → Chrome 侧可选「Win32 覆盖任务栏」；目标 EXE 侧选「最大化 + 强制覆盖任务栏」；个别游戏/客户端需要 F11 或 Alt+Enter。
- **按钮压住任务栏了** → X/Y 偏移调大；**想把按钮压到任务栏上** → 偏移填**负值**（例如 -20）。
- **找不到目标窗口** → 如果开了「窗口标题关键字」而标题不含该关键字，会被判为未找到（日志里会有提示），清空该关键字即可。
- **切换方向反了** → 只有关掉「严格模式」后才会出现：此时工具按"上次切换到的程序"判断方向（无记录则切 Chrome）。开着严格模式时，前台不是这两个程序就直接不动。
- **按钮被全屏窗口盖住** → 切换后工具会自动重新置顶 3 次（间隔 400ms），若仍被盖住请改用 Win32 覆盖方式。

## 8. 配置项速查（config.json）

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `ChromePath` | string | `C:\Program Files\Google\Chrome\Application\chrome.exe` | Chrome 完整启动路径（必须含文件名） |
| `TargetExePath` | string | `C:\Program Files\FleetView\FleetView.exe` | 目标程序完整启动路径 |
| `WindowTitleKeyword` | string | 空 | 目标窗口标题关键字（可选），多窗口时区分用；留空只用路径识别 |
| `ButtonTextWhenChrome` | string | `切到目标程序` | **当前前台是 Chrome 时**按钮显示的文字（点下去会切到目标程序） |
| `ButtonTextWhenTarget` | string | `切到浏览器` | **当前前台是目标程序时**按钮显示的文字（点下去会切到 Chrome） |
| `ButtonTextOther` | string | `—` | 前台既不是 Chrome 也不是目标程序时显示的文字 |
| `HideButtonWhenOther` | bool | `true` | 其它程序在前台时**自动隐藏悬浮按钮**（严格模式配套；隐藏期间托盘图标仍可操作） |
| `ButtonOpacity` | number | `0.75` | 悬浮按钮透明度，有效范围 0.3~1.0（悬停时自动变 1.0） |
| `ButtonFontSize` | number | `15` | 悬浮按钮字号（配置界面不提供，手改 JSON） |
| `ButtonText` | string | `切换` | 旧字段（v1.2 及以前），仅为兼容老 config.json 保留，**已不再使用** |
| `Anchor` | string | `BottomRight` | 按钮吸附的角：`BottomRight` / `BottomLeft` / `TopRight` / `TopLeft` |
| `OffsetX` | number | `12` | 水平偏移（像素）。**负值可压到任务栏上**，也用来避开输入法状态条/通知横幅等浮窗，范围 -1000~2000 |
| `OffsetY` | number | `12` | 垂直偏移（像素），同上 |
| `FreePosition` | bool | `false` | 是否使用**拖动记忆的位置**（按住按钮拖过后自动置 true，此时锚点/偏移不再生效） |
| `FreeX` / `FreeY` | number | 空 | 拖动记住的左上角坐标（屏幕物理像素）；点「复位到锚点」会清空 |
| `EdgeMargin` | number | `12` | 旧字段（v1.4 及以前）的单一边距；仅在 `OffsetX/OffsetY` 缺省时代入，老配置平滑升级 |
| `ChromeMode` | string | `SendF11` | Chrome **显示方式**（8 选 1，见下表） |
| `TargetMode` | string | `Maximize` | 目标 EXE **显示方式**（同一套 8 选 1） |
| `ChromeRect` | string | `0,0,50%,100%` | Chrome 自定义区域（仅 `CustomRect` 模式用） |
| `TargetRect` | string | `50%,0,50%,100%` | 目标 EXE 自定义区域（仅 `CustomRect` 模式用） |
| `StrictForegroundCheck` | bool | `true` | **严格模式**：只在前台窗口是 Chrome 或目标 EXE 时才切换；其它情况点按钮**不切换、不提示**（只在 app.log 记一行）。关闭后：按上次切换到的程序判断方向，无记录则切 Chrome |
| `IgnoreShellWindows` | bool | `true` | 忽略系统**通知横幅 / 任务栏 / 操作中心**抢前台（默认开）：这些窗口不影响按钮文字与显隐，也不会让严格模式误判成"其它程序" |
| `HotkeyEnabled` | bool | `true` | 是否启用**快速切换全局快捷键**（默认开） |
| `HotkeyText` | string | `Ctrl+Alt+S` | 快捷键组合。必须带 Ctrl/Alt/Shift/Win 中至少一个，或单独一个 F1~F24；非法值自动回落默认 |
| `Previous` | string | `Minimize` | 切换时旧窗口：`Minimize`（最小化）/ `StayInBackground`（留在后台） |
| `AutoStart` | bool | `true` | 开机自启，写入/删除 `HKCU\...\Run\SelfSwitch` |

### 显示方式（Chrome 与目标 EXE 各自独立设置，8 选 1）

| 显示方式 | 效果 | 适合 |
|---|---|---|
| `SendF11` | 发 F11 进入程序原生全屏（已全屏则跳过，不支持则回退覆盖任务栏） | **Chrome 首选** |
| `CoverTaskbar` | 铺满整屏 + 置顶（覆盖任务栏） | 通用，最稳 |
| `Maximize` | 普通最大化（**不**覆盖任务栏） | **目标程序首选**，对程序零侵入 |
| `MaximizeCoverTaskbar` | 先最大化再铺满整屏（覆盖任务栏） | 目标程序要盖住任务栏时 |
| `Windowed` | 窗口化：恢复成普通窗口（保留自身尺寸位置） | 想看两个程序的标题栏/随时拖 |
| `CustomRect` | 按 `ChromeRect`/`TargetRect` 摆放（**支持百分比**） | 左右分屏、固定尺寸 |
| `KeepCurrent` | 只切到前台，**不改窗口大小位置** | 窗口自己管的场景 |
| `SendAltEnter` | 发 Alt+Enter（不支持则回退覆盖任务栏） | 部分游戏/播放器 |

**自定义区域格式**：`x,y,w,h`，4 个值，每个可以是像素整数或百分比。

| 例子 | 效果 |
|---|---|
| `0,0,50%,100%` | 左半屏 |
| `50%,0,50%,100%` | 右半屏 |
| `0,0,1280,720` | 固定 1280×720（左上） |
| `25%,25%,50%,50%` | 居中半屏 |

> 把 Chrome 设成 `CustomRect` + `0,0,50%,100%`、目标程序设成 `CustomRect` + `50%,0,50%,100%`，
> 就变成**左右分屏**（而不是互相全屏切换）——默认值已经这么配好了，切一下模式即可。

> 手改 JSON 保存后**重启程序**生效；改完在配置界面点保存也会立即生效。
> 枚举值写成字符串，允许 JSON 注释和尾逗号。

## 9. 源码结构

```
SelfSwitch.csproj     工程文件（net8.0-windows，WPF + WinForms 托盘，单文件发布参数）
app.manifest          DPI 感知 PerMonitorV2 / 权限级别 asInvoker
App.xaml(.cs)         启动流程、单实例、配置加载、托盘、开机自启、全局异常兜底
AppPaths.cs           配置/日志落盘位置（EXE 同目录优先，不可写回落 %AppData%）
MainWindow.xaml(.cs)  悬浮按钮窗口（无边框/置顶/半透明/WS_EX_NOACTIVATE 不抢焦点）
ConfigWindow.xaml(.cs) 配置界面（13 个配置项）
AppConfig.cs          配置模型 + JSON 读写
Win32Helper.cs        Win32 P/Invoke 与封装（窗口/全屏/前台/权限/路径比较/前台事件钩子）
WindowFinder.cs       EnumWindows 按完整路径（+可选标题关键字）查主窗口
ForegroundWatcher.cs  实时跟随前台窗口（WinEvent 钩子 + 兜底轮询）→ 驱动按钮文字
ToggleService.cs      切换主逻辑（Chrome 发 F11 / 目标 EXE 最大化，各自可配）
TrayHelper.cs         托盘图标与气泡提示（5 秒去重）
Logger.cs             app.log 日志（2MB 轮转）
config.json           配置示例
build.bat             一键编译单文件 EXE
自启-任务计划程序-安装.bat / 卸载.bat   以管理员权限静默自启的备选方案
README.md             本文件（编译 / 配置 / 使用 / 自启 / 退出 / 管理员 / 排错）
需求对照与风险处置.md  逐条回复需求与风险点（含判定：已实现/已修改/不成立）
设计说明.md           项目结构、实现思路、关键技术点、已知限制（开发/维护看这个）
```
